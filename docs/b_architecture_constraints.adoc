== Architecture Constraints

This section outlines the non-negotiable technical, organizational, and regulatory boundaries governing the design, implementation, and operation of the Sovereign Air-Gapped Agentic Platform. All architectural decisions must strictly adhere to these rules to maintain defense-grade security and zero-trust isolation.

=== 1 Technical Constraints

The platform enforces a strict zero-trust perimeter, eliminating public network exposure and persistent access rights.

[cols="2,5", options="header"]
|===
| ID & Constraint | Specification & Rationale

| *TC-1: Air-Gapped Network Isolation*
| Zero public internet transit. Total absence of Internet Gateways (IGW) or NAT Gateways. All agentic workload traffic routes strictly internally via VPC Interface Endpoints (AWS PrivateLink). Any external routing to the Corporate On-Premises Datacenter via the Virtual Private Gateway (VGW) must strictly traverse an inline AWS Network Firewall for Deep Packet Inspection (DPI).

| *TC-2: Dynamic Secrets Enforcement*
| Zero static credentials. Autonomous agents are prohibited from holding hardcoded access rights. All interactions with corporate IT systems require the agent to dynamically request short-lived, ephemeral tokens from a centralized vault (e.g., AWS Secrets Manager, OpenBao).

| *TC-3: Cryptographic Sovereignty*
| Mandatory envelope encryption for data at rest and in transit using Customer Managed Keys (CMK). A strict separation of duties is enforced between infrastructure operators (compute deployment) and security custodians (key management).

| *TC-4: Immutable & Stateless Compute*
| The agentic orchestrator and reasoning runtimes (AWS Fargate & Step Functions) must operate on stateless compute nodes. Internal state retention is strictly limited to the Semantic Cache (Amazon ElastiCache) which must enforce hard limits: at-rest CMK encryption and short-lived Time-To-Live (TTL) eviction policies. No persistent custom application databases are permitted locally.

| *TC-5: Centralized AI Governance & FinOps Guardrails*
| Direct invocation of AWS Bedrock by compute resources is strictly prohibited. All inference requests must route through an Internal LLM Gateway Proxy (e.g., LiteLLM). This gateway is mandated to enforce structural guardrails, token rate-limiting, semantic caching, and precise FinOps cost attribution.
|===

=== 2 Organizational and Regulatory Constraints

These boundaries guarantee intellectual property protection and strict operational governance in compliance with industrial security policies (PSSI).

[cols="2,5", options="header"]
|===
| ID & Constraint | Specification & Rationale

| *OC-1: Zero Data Retention (ZDR)*
| Strict technical and contractual prohibition of model retraining by the inference provider (Amazon Bedrock). The provider must guarantee that prompt payloads, corporate context, and reasoning traces are immediately discarded post-inference. Internal platform traces and cached payloads must mechanically expire per TC-4.

| *OC-2: Deterministic Traceability*
| Every API call, delegated task, vault access, and agent reasoning step must be logged immutably to a centralized Security Information and Event Management (SIEM) system to meet aerospace/defense auditability standards.

| *OC-3: Geographic Data Residency*
| Primary infrastructure, vault storage, and sovereign LLM execution must be strictly provisioned within sovereign or heavily restricted European boundaries (e.g., SecNumCloud enclaves or specific `eu-west-3` boundaries).
|===

=== 3 Conventions and Standards

To ensure reusability and alignment with DevSecOps engineering standards, the following conventions are enforced.

[cols="2,5", options="header"]
|===
| ID & Convention | Specification & Tooling

| *CON-1: DevSecOps & IaC Validation*
| 100% Infrastructure as Code (Terraform/OpenTofu). Automated CI/CD pipelines must enforce mandatory static security analysis (tfsec, checkov) and linting before any infrastructure deployment is authorized.

| *CON-2: Documentation-as-Code*
| Architecture documentation is maintained alongside the codebase using AsciiDoc and the arc42 framework, ensuring technical specifications remain version-controlled and synchronized with the deployed infrastructure.
|===
